## Verification, page types, grouped findings, faster reading, OCR comparison, chest radiographs (next, 2026-10-29)

- **Document Verification** (new page). Each PDF page is shown beside what was extracted from it, with a box on the page for every value and statement read there. A reviewer marks each item as matching the page or differing (with the value, unit, specimen or assertion the page shows, or "not on the page"). Differences become one correction proposal for the four-eyes workflow; with every item checked and none differing, the finding can be confirmed. Page images come from `/uploads/{id}/pages/{n}/image` with every OCR line in which the identifier masks found something painted black; embedded-text pages say they cannot be masked.
- **Pages by document type.** Each page is typed by keyword and layout rules (laboratory, imaging with its modality, procedure, pathology, discharge summary, consultation, prescription, billing, unclassified) with the cues shown; a page that continues one ending "P.T.O" takes its type. Document Intelligence lists pages grouped by type and filters statements by page type. The rules are not evaluated on an annotated corpus.
- **Grouped findings.** A finding repeated in FINDINGS and IMPRESSION of one document is one row with every mention, section, page and quote (a toggle shows every mention); the Anatomy Studio evidence list groups the same way. Different documents are never merged.
- **Faster reading.** Scanned pages are read in parallel by a small pool of OCR engines (five photographed pages: 26 s to 15-19 s). The analysis caches the masked page text, page types and line boxes (encrypted like the upload, keyed by file hash and a fingerprint of the reading code, erased with the upload), so the text, verification and page-image views no longer run OCR again.
- **Masking.** A surname that is also a header word ("JOHN WARD", "DOE, BILL") is masked whole: a header word ends a name only when it reads as a label (with its separator or its value).
- **OCR engine comparison** (`benchmarks/ocr_benchmark.py`, `docs/validation/OCR_BENCHMARK.md`, Research Analytics): RapidOCR as MedTwin runs it, with the angle classifier, at the default threshold, and Windows OCR, on seeded synthetic pages in three conditions.
- **Chest radiograph research model** (`docs/validation/CHEST_RADIOGRAPH_RESEARCH_MODEL.md`): TorchXRayVision's pretrained classifier, anatomy segmenter and autoencoder (third-party, not evaluated by MedTwin; optional install and one-time weight fetch), behind the printed-document check and a both-lungs anatomy gate, with scores against the publisher's operating point, Grad-CAM attention by lung zone, anatomy outlines and a comparison with what the reports state. Results are findings pending review.
- **Documented regions on the 3-D atlas.** Sites such as "bilateral lower lobes" and "right hemidiaphragm" are read; atlas structures that an affirmed, certain, current statement names are tinted orange in the Anatomy Studio and listed as "named in a report, unconfirmed", apart from clinician-verified regions.
- Fixes found while building a demonstration case: an OCR-garbled small-print method between a test name and its value ("HbA1c dtyGSStrdi 7.8 %") no longer loses the value; Prognosis Studio no longer calls two undated images baseline and follow-up; the navigation marks one entry for a sub-page.

## Report data integrity: privacy screen, specimens, dates and ages (next, 2026-10-29)

Prompted by a review of a real report packet run through the app (findings recorded without patient details).

- **Privacy screen.** Header identifiers that the masks missed are now masked: labelled names ("Patient Name :", "NAME:") up to the next header label, referring and signing doctors ("Ref.by", "REF.BY:", "Performed BY:", "Dr"/"DR."), hospital, lab, registration and bill numbers ("MRNO", "MR.NO:", "UHID", "Reg-No"), labelled and OCR-glued phone numbers (including ten-digit numbers written like a range), addresses (labels, door numbers, town plus postcode) and names printed with the sex in brackets. Tests protect clinical text ("Trivial MR. MS", "No DR changes", "BP 120/80, Pulse", count ranges, "caused by:"). Every page records what was masked by category; the analysis provenance and `/uploads/{id}/text` report it with a "not verified by a person" status, and Document Intelligence shows it (an upload attested as de-identified that still held identifiers is called out) instead of labelling the text "de-identified".
- **Specimen per result.** The specimen was the first "Specimen:" line in the whole document, so a packet's haematology was recorded as serum: a later page said serum and the haematology page's "WHOLEBLOOD-EDTA" was OCR-glued. Each result now takes the specimen in its test name ("Serum Creatinine"), else the specimen line among its own lines, else the nearest one above it on the same page; OCR misspellings ("Specmen", "SerumPlasma", "Senum/Piasma", "EOTA") are read. A method is the result's own or one heading the page. Document Intelligence shows each result's specimen.
- **Dates per page.** A measurement takes its own page's sampling date, else that page's report date; a page with no date no longer borrows another page's. OCR-glued and hyphenated month dates ("August29th2024", "AUG27T2026", "29-Aug-2024") and "Report Out on" parse. Dates on one page more than a week apart are reported as conflicts, and Document Intelligence compares the entered examination date with each page's printed dates.
- **Ages.** eGFR (CKD-EPI 2021) is refused with `AGE_CONFLICTING (5, 75)` when the creatinine's own document prints different ages, instead of using the first one.
- **Comparison wording.** "Increased echotexture", "reduced attenuation" and similar tissue descriptors are no longer recorded as an interval change.
- Not done in this pass: grouping repeated findings across sections, an OCR engine benchmark, page-level document classification and a side-by-side document verification workspace.

## Vercel deployment, durable storage, provisioning and valve severity (next, 2026-10-29)

- **Vercel services** (configuration confirmed by the owner). `vercel.json`: `app` (Vite, root `.`) serves everything with an extension-less SPA fallback and the nginx security headers; `backend` (FastAPI on Vercel's Python runtime, root `backend/`) serves `/api/*` and `/health` with paths unchanged; `benchmarks` is not a service and there are no bindings. `backend/pyproject.toml` and `uv.lock` keep `requirements.txt`'s pins with headless OpenCV (Vercel's runtime has no libGL) and `vercel-blob`; `backend/vercel_build.py` stages the registries and evidence into the bundle, which Vercel limits to `backend/`; `.vercelignore` is a closed allowlist. An earlier uncommitted container draft and its always-failing build gate were moved to `_imports/superseded-vercel-container-draft-20261029/`. Operator guide: `docs/deployment/VERCEL_SERVICES.md`.
- **Durable storage.** PostgreSQL through `DATABASE_URL` (`postgres://` URLs get the installed psycopg driver); schema creation and migrations take an advisory lock so instances starting together do not race. With a private Blob store connected, every stored upload is also kept there, encrypted only (plaintext uploads are refused), an instance without the file fetches it on first read, and erasure removes both copies. Tested with an in-memory store and with two API processes sharing a real PostgreSQL 16 server.
- **Temporary storage is visible.** On a read-only host without a database and object store, every signed-in page warns that data is temporary and synthetic-only. A 413 from the platform (Vercel's 4.5 MB cap) reads as a size refusal instead of a raw error page.
- **Operator provisioning.** `python -m app.provision` creates or verifies a clinician, researcher or administrator in the deployment's database (password from the environment, audit-logged). No public endpoint grants these roles and the development seed is refused in production.
- **Valve findings.** "Mitral regurgitation", "Aortic stenosis" and the other six valve lesions replace "Valvular heart disease", and the written severity ("Trivial", "mild to moderate") is kept as a SEVERITY cue on its finding. A "Grade X" ending the text before a finding stays with the finding before it (OCR joins table columns: "Mitral regurgitation-Grade Trivial Mitral stenosis -Nil").
- **Containers.** The backend image now holds `dataset_registry/tasks.json`, so the dataset task audit answers in Docker (61 datasets). Full Compose run with the encrypted database default and the worker profile: healthy services running as non-root, security headers, a worker-run job, encrypted upload and SQLCipher database files with no fixture text, restart persistence, clean shutdown (worker and frontend exit 0, backend 143 on SIGTERM).

## Third photographed-report pass and serverless-safe backend (next, 2026-10-29)

- **OCR orientation.** Pages are read without RapidOCR's per-box 180-degree classifier. On the owner's three photographed packets it turned 13 of 2,525 upright boxes over and nothing else changed: units became garbage ("mg/dl" read as "Ip/Bw", "g/dL" as "1p/6"), so calcium, urea and creatinine rows were dropped, and one negated spine-report line ("...no features suggestive of myelomalacia / cord") was read upside down below the text score and lost, leaving "atrophy seen." as an uncertain fragment. A page upside down as a whole reads below 0.85 confidence and is read again turned 180 degrees (synthetic test).
- **Laboratory rows.** A unit wrapped under its column ("millioncells/" over "µL") is joined to the row above; count units that lost their slash ("CellCumm") or read µL as "PL" are accepted (cells per picolitre is never a count unit); "TOTALWBC" and "TOTALRBC" match. On the neurology packet 32 printed values are read with their ranges instead of 25, and on the colonoscopy packet direct and indirect bilirubin and total protein are no longer dropped; nothing previously read was lost on any packet. RDW-SD, whose unit was read as "L", and a range read as "1,000-3.400" stay unread and indeterminate rather than guessed.
- **Glued words.** A word glued to a number ("stroke6yearsback") and a lone capital ending a word ("VitaminD3", which segmented as "Vita minD") are separated for rule matching only; quoted spans still reproduce the page exactly. Prior stroke is now recorded as historical on both neurology visits.
- **Serverless hosts.** With a read-only code directory the default database and uploads go to the temp directory, and `/system/health` and readiness report `temporary_storage`. Rate limits use Vercel's forwarded client address only when `VERCEL=1`; the commit is taken from `VERCEL_GIT_COMMIT_SHA` when none is configured; benchmark results and the dataset registry are read below `MEDTWIN_PROJECT_ROOT` (benchmark results were looked up outside it, so containers never found them).
- **No ML stack required to start.** The API starts and answers without PyTorch, torchvision or MONAI (a subprocess test blocks them): health and GPU telemetry report no CUDA, the masked fusion layer moved to `fusion_layer.py` (the case-level gate never evaluates it), and image preprocessing metadata uses NumPy. Research models still report a missing dependency instead of running.

## Applicability gate, EDF, DICOM series, database encryption, portal, CI browser suite (next, 2026-10-28)

- **Image applicability gate.** Every 2-D research model refuses images unlike its training images before it runs, whatever modality is declared: input statistics and every network stage, a probabilistic-PCA Mahalanobis distance per stage fitted on the training split, the mean of stage scores against the 0.99 quantile of the validation split (`app/services/image_ood.py`, `scripts/build_image_ood_references.py`). Own-test false refusals 0–11.7%; other image families refused 68–100% except GastroVision on angiograms (14.7%); the owner's chest X-ray film photo and four other photos were refused by all seven models. References are bound by SHA-256 to their checkpoints (`docs/validation/IMAGE_APPLICABILITY_GATE.md`). With inline execution the gates answer before a job is queued; refusals are typed 400s.
- **EEG and physiological recordings.** EDF, EDF+ and BDF uploads (`SIGNAL` modality) are checked structurally (header length, numeric fields, ranges, record size) and shown channel by channel with annotations (Multimodal). The header's patient and recording identification fields are never displayed or stored in findings; a filled field raises a warning. No model.
- **DICOM series.** Assembled series render plane by plane with windowing (Medical Imaging, DICOM series) and run through the cardiac MRI segmenter with the same checks as a NIfTI frame; series written from the 98 public test frames gave identical inputs and masks (`docs/validation/SERIES_INFERENCE_PARITY.json`). The in-plane orientation of scanner series is an assumed convention, stated in every output.
- **Database encryption.** `MEDTWIN_DB_ENCRYPTION=sqlcipher` encrypts the whole SQLite file and WAL (raw 256-bit key from `MEDTWIN_DB_KEY_FILE`/`MEDTWIN_DB_KEY`); Compose defaults to it and fails closed without a key; `scripts/encrypt_database.py` writes a verified encrypted copy and never touches the original. The SQLCipher dialect's per-thread pool closed connections under concurrent requests; the engine now uses a queue pool (found by the browser suite).
- **Patient and caregiver portal.** Clinicians link personal accounts to a case as PATIENT or CAREGIVER; patients add or remove caregivers. The read-only "My record" page shows the case documents and results from clinician-confirmed report findings (approved corrections applied, printed intervals only); research-model output and unreviewed extraction are never shown, and these links open no clinical endpoint, case list or analytics.
- **Browser regression in CI.** `tools/browser-qa/e2e` (Playwright, Chromium in CI) starts a throwaway encrypted stack and checks sign-in, every page, report, HL7 and EDF uploads and the portal.
- **Docker.** Full Compose run executed: worker-run job, encrypted uploads and database, restart persistence, clean shutdown. The worker ignored SIGTERM during start-up (handler installed after ~10 s of imports); it now installs it first and Compose runs `init: true`. The frontend runs as unprivileged nginx (uid 101) with CSP and other security headers.
- **Registration.** Reviewed landmark manifests: a verified clinician proposes landmark pairs with held-out landmarks declared up front, a second verified clinician approves or rejects (four-eyes), and only an approved manifest within its held-out TRE limit lifts a finding to L2. Re-running the registration gate for a finding no longer fails on the unique mapping row.
- **Extraction.** A printed range's upper bound with its unit ("(Reference range 12.0 - 15.5 g/dL)") no longer ends the reference column.

## HL7 v2 observation-result import (next, 2026-10-28)

- `.hl7` uploads (content must start with an MSH, FHS or BHS segment) are clinical reports. `backend/app/services/hl7_import.py` renders only OBR, OBX and NTE content; PID, PD1, NK1, PV1, PV2, ORC, insurance and guarantor segments and the MSH sender/receiver fields are never read, so they cannot reach stored text, rules or the database. Escapes (`\F\`, `\S\`, `\T\`, `\R\`, `\E\`, `\.br\`, `\X..\`) are decoded.
- Each OBX becomes one canonical line, and its measurement quotes that line: NM and single-number SN values (with comparator), OBX-6 units through the shared UCUM mapping, OBX-7 ranges (`a-b`, `<b`, `>=a`; inclusivity kept), OBX-8 flags, OBX-14 or OBR-7 dates, and the documented OBX-3 code (LOINC preferred from the primary or alternate triplet; a code with no MedTwin analyte keeps its own name). Results marked X, D or W in OBX-11 are rendered with that status and produce no measurement; ranges and ratios are not numbers. Text and coded results and NTE comments go through the clinical-statement rules.
- The modality catalogue lists HL7 v2 as supported (no model). Tests: `backend/tests/test_hl7_import.py` (synthetic message with marker values that must not appear in the text).

## ECG and cardiac MRI upload inference, Docker build fix (next, 2026-10-28)

- **ECG.** `backend/app/services/ecg_inference.py` reads WFDB format-16 header/signal pairs exactly (gain, baseline, unit, per-lead checksum and first sample, which also prove the two uploads belong together) and CSV records with a time column in seconds and a user-declared amplitude unit. Records outside the trained contract (100 Hz, 1,000 samples, the 12 standard leads, finite samples, peak ≤ 10 mV, no flat lead) are refused with a typed reason; nothing is resampled, cropped or padded. The compact 1-D ResNet is rebuilt in the backend and loaded with strict key/shape checks; Platt scaling and validation thresholds come from the checkpoint. Run from Multimodal.
- **Cardiac MRI.** `backend/app/services/volume_inference.py` accepts one 3-D NIfTI frame with square in-plane pixels, the slice axis last and voxel spacing inside the development range recorded by `scripts/build_acdc_input_envelope.py` (198 development cases; refuses 2 of 100 publisher test frames). Inference matches the evaluation: non-zero z-score, sliding window at the training patch, overlap 0.25, float16 autocast on CUDA. Output: per-structure voxel counts and volumes from the header voxel size, per-axial-slice masks drawn on the viewer's slice, and the model's held-out volume agreement. Ejection fraction is not computed from single uploads.
- **Gate and route.** `POST /uploads/{id}/research-inference` takes `companion_upload_id` (WFDB signal file, same case, current) and `amplitude_unit` (CSV). Content is checked before a job is queued, so out-of-contract uploads are typed 400 refusals; execution repeats the checks. Provenance records the companion file hash and declared unit.
- **Parity.** `scripts/verify_upload_inference_parity.py` ran the server path on the public held-out sets: ECG 2,161 of 2,163 records compared, max probability difference 0.0024, 2 of 10,805 threshold decisions differ; cardiac MRI 98 of 98 masks identical (`docs/validation/UPLOAD_INFERENCE_PARITY.md`).
- **Docker.** `Dockerfile.frontend` ran `npm run check`, which now compiles into `.cache/build-check`, so the nginx stage found no `dist` and the CI image build failed. It now runs typecheck, lint and the production build. A stray TotalSegmentator workflow left by an archive extraction (ignored, never published) was removed.
- Tests: `backend/tests/test_signal_and_volume_inference.py` (20, synthetic signals, volumes and randomly initialised networks); browser check on an isolated QA stack with one public PTB-XL record and one public ACDC frame.

## Cardiac MRI, inference precision, medical naming and Supabase client (next, 2026-10-25)

- **Cardiac MRI.** The repository owner authorized local, non-commercial research training on the cardiac cine-MRI set after review of the publisher's statement that the data and ground truth remain publicly available with a mandatory citation (no licence text exists); the authorization, scope and evidence are recorded in the dataset registry, and availability alone still never opens the gate. The audit gains a volumetric preparer that summarises the same manifest the trainer validates. A 3-D U-Net trained through `ml_training.volumetric` (epoch 41 of 60 selected on validation) scored, on the 50 frozen test patients (100 ED/ES volumes): mean case macro Dice 0.750 (95% patient-bootstrap CI 0.719–0.778; LV 0.812, myocardium 0.731, RV 0.707); LV ejection fraction against the reference masks MAE 9.1 points, bias −5.8, r 0.852. - **Medical naming.** Datasets, tasks, models, anatomy assets, frameworks and runtimes are shown under medical names (`src/lib/displayNames.ts`, registry display names, anatomy labels in the pipeline catalogue and manifest); generated free text keeps its source names on disk and is neutralised for display. Original names, creators, licences and citations appear only on the new `/attribution` page (Data sources and licences), linked from Settings, Validation Center, Medical Imaging and Live Anatomy Studio.
- **Supabase.** `@supabase/supabase-js` and `@supabase/ssr` installed; `src/lib/supabase/client.ts` is the browser client from the Next.js registry block, ported to Vite (`envPrefix` admits the `NEXT_PUBLIC_` variable names; values live in the git-ignored `.env.local`). The block's server and middleware files need a Next.js server runtime and were not added. No patient data is sent to the service.
