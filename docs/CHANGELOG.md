## HL7 v2 observation-result import (next, 2026-10-28)

- `.hl7` uploads (content must start with an MSH, FHS or BHS segment) are clinical reports. `backend/app/services/hl7_import.py` renders only OBR, OBX and NTE content; PID, PD1, NK1, PV1, PV2, ORC, insurance and guarantor segments and the MSH sender/receiver fields are never read, so they cannot reach stored text, rules or the database. Escapes (`\F\`, `\S\`, `\T\`, `\R\`, `\E\`, `\.br\`, `\X..\`) are decoded.
- Each OBX becomes one canonical line, and its measurement quotes that line: NM and single-number SN values (with comparator), OBX-6 units through the shared UCUM mapping, OBX-7 ranges (`a-b`, `<b`, `>=a`; inclusivity kept), OBX-8 flags, OBX-14 or OBR-7 dates, and the documented OBX-3 code (LOINC preferred from the primary or alternate triplet; a code with no MedTwin analyte keeps its own name). Results marked X, D or W in OBX-11 are rendered with that status and produce no measurement; ranges and ratios are not numbers. Text and coded results and NTE comments go through the clinical-statement rules.
- The modality catalogue lists HL7 v2 as supported (no model). Tests: `backend/tests/test_hl7_import.py` (synthetic message with marker values that must not appear in the text).

## Photographed reports, second pass (next, 2026-10-28)

- **OCR.** Rows are grouped on the de-skewed baseline; the detection box threshold is 0.3, which recovered a dropped pathology line and turned an affirmed "dysplasia/ malignancy" into the printed negation; sideways pages are read upright (orientation chosen by recognition confidence, boxes mapped back, `rotation_degrees` in page provenance); a lower-case line after a lost-line gap is preceded by a blank line; fullwidth punctuation becomes ASCII.
- **Statements.** Fragment guard (`OCR_FRAGMENT`, `UNCERTAIN`) for lower-case starts after a sentence end or blank line; colon, dash, bare and same-line headings with a page-break reset; post-negation scope stops at the next uncoordinated entity; "Ni" for a truncated "Nil" after ":"/"-"; glued shorthand ("S/Ploopileostomy…") segmented; advert exclusion per sentence on long lines.
- **Laboratory tables.** Method/specimen left-column lines no longer end the printed reference column; results printed on the method/specimen line above or below their test name are paired only under unit and label checks; unspaced ages ("52Yr3M"); "Upto" bounds never read as dates; unlabelled method text before a value; OCR-variant names and flags.
- Details and the values deliberately left unread: `docs/verification/CLINICAL_NLP_ERROR_AUDIT.md` (fixes 21–31). Tests: `backend/tests/test_report_photo_extraction.py` (47; every new fixture fails on the previous code).

## ECG and cardiac MRI upload inference, Docker build fix (next, 2026-10-28)

- **ECG.** `backend/app/services/ecg_inference.py` reads WFDB format-16 header/signal pairs exactly (gain, baseline, unit, per-lead checksum and first sample, which also prove the two uploads belong together) and CSV records with a time column in seconds and a user-declared amplitude unit. Records outside the trained contract (100 Hz, 1,000 samples, the 12 standard leads, finite samples, peak ≤ 10 mV, no flat lead) are refused with a typed reason; nothing is resampled, cropped or padded. The compact 1-D ResNet is rebuilt in the backend and loaded with strict key/shape checks; Platt scaling and validation thresholds come from the checkpoint. Run from Multimodal.
- **Cardiac MRI.** `backend/app/services/volume_inference.py` accepts one 3-D NIfTI frame with square in-plane pixels, the slice axis last and voxel spacing inside the development range recorded by `scripts/build_acdc_input_envelope.py` (198 development cases; refuses 2 of 100 publisher test frames). Inference matches the evaluation: non-zero z-score, sliding window at the training patch, overlap 0.25, float16 autocast on CUDA. Output: per-structure voxel counts and volumes from the header voxel size, per-axial-slice masks drawn on the viewer's slice, and the model's held-out volume agreement. Ejection fraction is not computed from single uploads.
- **Gate and route.** `POST /uploads/{id}/research-inference` takes `companion_upload_id` (WFDB signal file, same case, current) and `amplitude_unit` (CSV). Content is checked before a job is queued, so out-of-contract uploads are typed 400 refusals; execution repeats the checks. Provenance records the companion file hash and declared unit.
- **Parity.** `scripts/verify_upload_inference_parity.py` ran the server path on the public held-out sets: ECG 2,161 of 2,163 records compared, max probability difference 0.0024, 2 of 10,805 threshold decisions differ; cardiac MRI 98 of 98 masks identical (`docs/validation/UPLOAD_INFERENCE_PARITY.md`).
- **Docker.** `Dockerfile.frontend` ran `npm run check`, which now compiles into `.cache/build-check`, so the nginx stage found no `dist` and the CI image build failed. It now runs typecheck, lint and the production build. A stray TotalSegmentator workflow left by an archive extraction (ignored, never published) was removed.
- Tests: `backend/tests/test_signal_and_volume_inference.py` (20, synthetic signals, volumes and randomly initialised networks); browser check on an isolated QA stack with one public PTB-XL record and one public ACDC frame.

## Cardiac MRI, inference precision, medical naming and Supabase client (next, 2026-10-25)

- **Cardiac MRI.** The repository owner authorized local, non-commercial research training on the cardiac cine-MRI set after review of the publisher's statement that the data and ground truth remain publicly available with a mandatory citation (no licence text exists); the authorization, scope and evidence are recorded in the dataset registry, and availability alone still never opens the gate. The audit gains a volumetric preparer that summarises the same manifest the trainer validates. A 3-D U-Net trained through `ml_training.volumetric` (epoch 41 of 60 selected on validation) scored, on the 50 frozen test patients (100 ED/ES volumes): mean case macro Dice 0.750 (95% patient-bootstrap CI 0.719–0.778; LV 0.812, myocardium 0.731, RV 0.707); LV ejection fraction against the reference masks MAE 9.1 points, bias −5.8, r 0.852. All volumes are overestimated (no prespecified connected-component post-processing), so the indices are research evidence only. Registered `READY_UNVALIDATED`, evaluation-only (`volume_nifti`), with a Validation Center view of structures and cardiac indices.
- `ml_training/volumetric_report.py`: per-structure Dice with patient-bootstrap intervals, 3-D HD95 and ASSD in millimetres, and per-patient LV/RV end-diastolic and end-systolic volumes, ejection fractions and LV myocardial mass from predicted and reference masks (bias, limits of agreement, mean absolute error, Pearson r). Voxel volume comes from the NIfTI header pixdim because these files' sform affine is unit-scaled; the manifest's affine-derived spacing (1 mm) is therefore not used for volumes.
- `ml_training/volumetric.py`: strict deterministic algorithms refused the first CUDA training step (cross-entropy has no deterministic CUDA kernel); CUDA now runs in warn-only mode and the run records it. The failed first attempt is kept and marked `FAILED`.
- **Inference precision.** Classifiers and segmenters were evaluated under bfloat16 autocast, but the adapter served them in float32; for the leukaemia-cell classifier this changed 84 of 1,867 held-out predictions (accuracy 0.807 → 0.787). The adapter now reproduces the evaluated precision on CUDA (parity: 21/21 top classes, maximum probability difference 0.0008, was 0.135) and every output states its precision; CPU inference is labelled as differing.
- **Medical naming.** Datasets, tasks, models, anatomy assets, frameworks and runtimes are shown under medical names (`src/lib/displayNames.ts`, registry display names, anatomy labels in the pipeline catalogue and manifest); generated free text keeps its source names on disk and is neutralised for display. Internal identifiers, file paths and research documents are unchanged. Original names, creators, licences and citations appear only on the new `/attribution` page (Data sources and licences), linked from Settings, Validation Center, Medical Imaging and Live Anatomy Studio.
- **Supabase.** `@supabase/supabase-js` and `@supabase/ssr` installed; `src/lib/supabase/client.ts` is the browser client from the Next.js registry block, ported to Vite (`envPrefix` admits the `NEXT_PUBLIC_` variable names; values live in the git-ignored `.env.local`). The block's server and middleware files need a Next.js server runtime and were not added. No patient data is sent to the service.
- Dataset audit: the C-NMC subject split joins subjects that share pixel-identical images (14 subject pairs; 3 training subjects linked to the test set removed). The registry test now expects the 32 task units the audit source defines (the previous generated file listed 34; the two extra entries are not defined by the current source) with cardiac MRI `READY_FOR_TRAINING`.
