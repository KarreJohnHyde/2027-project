## Welcome page and remembered browser sessions (2026-11-10)

- **Root cause of "Request failed (502 Bad Gateway)"**: `npm run dev` and the Figma Make preview run only Vite. Its `/api` proxy forwards to `127.0.0.1:8000`, and with no backend there the proxy's `ECONNREFUSED` became an empty 502. The proxy now answers `503 {"code": "BACKEND_UNREACHABLE"}` with the target and the start command. The client treats network errors and 502/503/504 as "server unavailable": idempotent calls retry twice (0.5 s, 1.5 s), then the welcome page shows a notice with Retry.
- **Welcome page**: the page has the heading "Welcome to MedTwin" and the line "Enter your details to begin." Name and role (Researcher, Student, Clinician, Other) are required; age and gender are optional. The buttons are **Enter MedTwin** and **Try Demo**, and the page links to the fictional teaching cases. The page has no username, password, sign-in or account-creation controls. Accounts registered with a password sign in at `/account`.
- **Remembered browser** (`app/services/browser_sessions.py`, table `browser_sessions`): the session is an opaque 256-bit value in an `HttpOnly`, `SameSite=Lax` cookie on `/api`, and only its SHA-256 is stored. Rotation happens after 12 hours of use, with a 2-minute grace for requests in flight. Sign-out revokes the session on the server. Cookie-authenticated writes require `X-MedTwin-Client`, which guards against CSRF. Bearer tokens still work for API clients and tests, and the web app no longer keeps any token in `localStorage`. A token stored by an earlier version is exchanged once, through `/auth/session/claim`, and then removed.
- **No identity matching**: people are never matched by name, age, gender, IP or device. `Idempotency-Key` makes a retried Enter MedTwin or Try Demo reuse the profile that the same press created. A stated role never changes the account role (`public`).
- **Try Demo no longer waits for the analysis**: starting a demo used to analyse all three fictional documents inside the request. On a workstation with the WSL NLP tools that took over a minute, long enough for a proxy to time out. The demo now answers once the documents are stored and queued, the ordinary analysis runs after the response (or on the worker), and the guest notice shows progress and loads each result as it finishes. A retried press reuses its `Idempotency-Key` and reopens the same demo.
- **Sign-in no longer waits behind an analysis**: `execute_upload_analysis` inserted its pending run before reading the document. On SQLite that opened a write transaction and held the write lock for the whole analysis, tens of seconds per report with the WSL NLP tools. Every sign-in (which writes an audit row) and every upload elsewhere waited. Because `login` is an async route, the wait also stalled the event loop. The run is now written once the adapter returns, and the queued job still shows that the analysis is running. The browser suite checks that a sign-in during a demo's analysis answers within 10 s.
- **Roles**: the welcome page now offers research and education roles, clinical roles (doctor, nurse, clinical staff, surgeon and others), 48 medical specialties, 20 healthcare departments, and patients and families, grouped in one list. The backend accepts exactly this list (`app/schemas/entry_roles.py`), and a test keeps it identical to the frontend's. No role grants anything.
- **Reaching registered accounts**: `scripts/account_access.py` lists registered accounts, issues one-time sign-in links (single use, 15 minutes, only the SHA-256 is stored, and the code travels in the URL fragment), and shares cases with another registered account as their creator would. All three actions are audited. A link code can never be used as a session cookie.
- **Open workspace** (owner's decision, 2026-11-10: "everyone should see all the pages ... remove all the sign in options"): `MEDTWIN_OPEN_WORKSPACE_ACCOUNT` names a registered, non-administrator account. Every browser opens the workspace as that account with no sign-in, and every case is shared. "My record" lists every workspace case with reviewed results only, and the sidebar says the workspace is open. The backend refuses the setting on Vercel and in production. The dev launcher reads it from the untracked `.cache/dev-stack/settings.json`. Uploads still require the de-identification confirmation.
- **Connection pool**: every signed-in request holds a database connection for its whole duration. Opening the workspace sends about fifteen requests at once, some slow, and SQLAlchemy's default SQLite pool is 5 + 10 connections. While an analysis ran, one browser could therefore exhaust the pool, and a sign-in elsewhere waited 30 s and failed with a 500. File SQLite now uses 20 + 20, matching the API's 40 worker threads.
- **Migration**: one new table, created additively. No existing table, account, case, upload or audit record is changed.

## Scan formats, cardiac and head CT series, resumable training, TB and LIDC (2026-11-06, evening)

Owner decisions this session: the LIDC-IDRI 300-patient subset (28 GB, CC BY 3.0) and the NLM tuberculosis sets were approved for download; the DeepSA and PhysioNet requests are drafted for the owner to send (nothing was sent).

- **Security fix**: an NRRD header can name a separate data file (`data file:`), and a MetaImage header an `ElementDataFile`; ITK reads that path anywhere on the machine, so an upload could have displayed another local file's bytes as an image. Such headers are now refused at upload and before every read (`imaging_readers.check_attached_data`).
- **DICOM frames for 2-D models** (`app/services/dicom_raster.py`): Modality LUT, then the model's declared DICOM window or the frame's own VOI (LINEAR, LINEAR_EXACT, SIGMOID, VOI LUT sequence), MONOCHROME1 inverted, 8-bit stored values used as stored, colour decoded to RGB; the Modality tag must fit the declared input type; multi-frame files need a frame choice (the frame on display). The converted frame passes the same document and applicability gates; the conversion is recorded with the run. A synthetic RGB endoscopy frame gives exactly the same output and applicability score as DICOM and as PNG. Reference masks and boxes attach to single-frame DICOM.
- **Volume formats**: NRRD and single-file MetaImage feed the volume models in NIfTI voxel order with the same checks; orientation codes are compared in NIfTI terms. A DICOM series for a CT model whose development frames record an orientation is permuted and flipped into it (no resampling) and the mask returned to the series grid.
- **RSNA export window** (`docs/validation/RSNA_PNG_WINDOW_ESTIMATE.md`): every RSNA PNG uses exactly 79 inner grey levels in steps of 255/80, so the export window is 80 HU wide with truncation; level 40 HU from tissue peaks (estimated). Declared on the head-CT model for DICOM input.
- **Cardiac scanner series** (`docs/validation/CARDIAC_SCANNER_SERIES.md`): cine series are assembled for a chosen phase (trigger-time ordinal); MR, double-oblique and slice-count checks plus the requester's attestation; the axis convention is chosen among 16 by anatomy (right ventricle anterior-right in patient coordinates, shrinking left ventricle, development layout). - **Neighbouring-slice haemorrhage model** (`ml_training/rsna_ich_25d.py`, training queued): slice below, slice, slice above as channels, the single-slice model's patient split and a paired comparison; serving on an assembled head CT series windowed like the training PNGs, every slice checked against the applicability reference (more than half outside refuses the series).
- **Resumable training**: the detector, echo, multichannel volume and 2.5-D trainers write their state after every epoch and resume after a shutdown (a power-off at 17:58 had ended the fracture run at epoch 15 of 20 with nothing saved).
- **Data**: NLM Shenzhen and Montgomery radiographs mirrored from NLM's data server with per-file MD5 checks (Open-i was down); `scripts/register_nlm_tb_dataset.py` (terms from the read-me files, near-duplicate-aware splits). ## Verification, page types, grouped findings, faster reading, OCR comparison, chest radiographs (next, 2026-10-29)

- **Document Verification** (new page). Each PDF page is shown beside what was extracted from it, with a box on the page for every value and statement read there. A reviewer marks each item as matching the page or differing (with the value, unit, specimen or assertion the page shows, or "not on the page"). Differences become one correction proposal for the four-eyes workflow; with every item checked and none differing, the finding can be confirmed. Page images come from `/uploads/{id}/pages/{n}/image` with every OCR line in which the identifier masks found something painted black; embedded-text pages say they cannot be masked.
- **Pages by document type.** Each page is typed by keyword and layout rules (laboratory, imaging with its modality, procedure, pathology, discharge summary, consultation, prescription, billing, unclassified) with the cues shown; a page that continues one ending "P.T.O" takes its type. Document Intelligence lists pages grouped by type and filters statements by page type. The rules are not evaluated on an annotated corpus.
- **Grouped findings.** A finding repeated in FINDINGS and IMPRESSION of one document is one row with every mention, section, page and quote (a toggle shows every mention); the Anatomy Studio evidence list groups the same way. Different documents are never merged.
- **Faster reading.** Scanned pages are read in parallel by a small pool of OCR engines (five photographed pages: 26 s to 15-19 s). The analysis caches the masked page text, page types and line boxes (encrypted like the upload, keyed by file hash and a fingerprint of the reading code, erased with the upload), so the text, verification and page-image views no longer run OCR again.
- **Masking.** A surname that is also a header word ("JOHN WARD", "DOE, BILL") is masked whole: a header word ends a name only when it reads as a label (with its separator or its value).
- **OCR engine comparison** (`benchmarks/ocr_benchmark.py`, `docs/validation/OCR_BENCHMARK.md`, Research Analytics): RapidOCR as MedTwin runs it, with the angle classifier, at the default threshold, and Windows OCR, on seeded synthetic pages in three conditions.
